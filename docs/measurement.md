# 직접 측정: 수작업 vs 이 도구

같은 엑셀 파일을 **엑셀로 직접 취합·검증했을 때**와 **이 도구로 처리했을 때** 걸린 시간과 찾은 오류 수를 비교했습니다.
화면 맨 위 숫자 카드의 "11분 → 1분", "14 / 14"는 이 측정 결과입니다(분 단위, 초는 버림).

> 측정자가 제작자 본인이고 1회만 측정했습니다. 아래 [한계](#한계)를 함께 읽어 주세요.

## 상황 설정

- **파일**: 수입검사 샘플 3개 파일(`samples/incoming_inspection/`), 데이터 합계 45행
  - 파일마다 열 이름·열 순서·날짜 표기가 다르고, 한 파일은 제목 줄 때문에 머리글이 3행에 있습니다.
- **심어 둔 오류**: 14건(`samples/expected_errors.md`의 수입검사 부분). 필수값 빈칸, 형식 오류, 범위 밖 값, 허용값 아닌 값, 파일 간 중복 행이 섞여 있습니다.
- **측정자**: 제작자 본인

## 단계

### 수작업 (엑셀)
1. 3개 파일의 데이터를 한 시트로 모은다(열 이름·순서를 맞춤).
2. 날짜 표기를 하나로 통일한다.
3. 오류를 찾아 표시한다.

### 이 도구
1. 3개 파일을 올린다.
2. 열 매칭 확인표를 확인한다.
3. 취합·검증을 실행한다.
4. 결과 엑셀을 내려받는다.

## 규칙

- **시간**: 수작업은 취합부터 오류 표시까지, 도구는 업로드부터 결과 엑셀 다운로드까지 잽니다.
- **검출 수**: 정답지(`samples/expected_errors.md`)의 오류 14건 중 몇 건을 찾았는지 셉니다.
- **잘못 표시**: 정답지에 없는데 오류라고 표시한 수를 셉니다. 도구가 중복 행의 짝(먼저 나온 행)에도 "중복 행"을 표시하는 것은 정답지 규칙에 따라 정답으로 봅니다.

## 결과

| 방법 | 걸린 시간 | 찾은 오류 | 잘못 표시 |
|---|---|---|---|
| 수작업 (엑셀) | 11분 42초 | 8 / 14 | 0건 |
| 이 도구 | 1분 27초 | 14 / 14 | 0건 (정답지 기준, 자동 테스트로도 확인) |

- 시간은 약 8배 줄었습니다(702초 → 87초).
- 수작업에서 놓친 오류는 6건입니다.
- 도구의 "잘못 표시 0건"은 이 측정 때 센 값이 아니라, 같은 샘플을 정답지와 대조하는 자동 테스트(`tests/test_samples.py`)의 결과입니다.

## 한계

- **측정자가 제작자 본인입니다.** 샘플에 오류가 있다는 것, 어떤 종류의 오류인지를 알고 찾았습니다. 오류가 있는지 모르는 실제 사용자라면 수작업 검출 수는 더 적고 시간은 더 걸릴 수 있습니다. 즉 **실제 차이는 더 클 수 있습니다.**
- **1회 측정입니다.** 같은 사람이 반복하거나 다른 사람이 측정하면 값이 달라질 수 있습니다.
- **작은 샘플입니다.** 3개 파일, 45행 기준입니다. 파일 수·행 수가 늘어나면 수작업 시간은 더 늘어나는 경향이 있지만, 이번에는 측정하지 않았습니다.
- 도구 시간에는 열 매칭 확인표를 훑어보는 시간이 포함됩니다. 열 이름이 동의어 사전에 없어서 매칭을 직접 고쳐야 하는 파일이라면 더 걸립니다.

## 값을 바꿀 때

화면 숫자 카드는 `project_stats.toml`의 `[measurement]` 값을 읽습니다. 다시 측정했다면 그 값과 이 문서의 결과 표를 함께 고치세요. 둘이 다르면 `tests/test_project_stats.py`가 실패합니다.
